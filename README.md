# Виджет Банк


**Цель проекта:** создать новую фичу для личного кабинета клиента, которая показывает несколько последних успешных банковских операций клиента.


## Основные функции


В проекте реализованы следующие функции:

### Модуль `masks`


* **`get_mask_card_number`** — маскирует номер банковской карты по шаблону «XXXX XX** **** XXXX».
* **`mask_account_card`** — обрабатывает информацию о банковских картах и счетах, возвращая строку с замаскированными данными.
* **`get_date`** — преобразует строку с датой из формата ISO в формат «ДД.ММ.ГГГГ».

### Модуль `processing`

* **`filter_by_state`** — фильтрует список словарей по значению ключа `'state'`.
* **`sort_by_date`** — сортирует список словарей по дате (ключ `'date'`).


### Модуль `widget`

Основной модуль, объединяющий функциональность для отображения виджета с последними успешными операциями клиента.


## Тестирование


Проект имеет комплексную систему тестирования, построенную на базе `pytest`. Структура тестов организована по модульному принципу для удобства поддержки и расширения.


### Структура тестовых файлов

* **`conftest.py`** — содержит все фикстуры с подробными докстрингами. Фикстуры предоставляют тестовые данные для различных сценариев, включая:
    * валидные и невалидные номера карт;
    * граничные случаи (нули, девятки и т. д.);
    * данные с разными статусами операций (`EXECUTED`, `CANCELED`, `PENDING`);
    * даты в различных форматах ISO;
    * списки с отсутствующими ключами (`state`, `date`).
* **`test_masks.py`** — тесты модуля `masks`. Проверяют корректность маскирования:
    * номеров банковских карт;
    * счетов;
    * обработки различных типов входных данных (строки, числа).
* **`test_processing.py`** — тесты модуля `processing`. Проверяют:
    * фильтрацию операций по статусу (`filter_by_state`);
    * сортировку операций по дате (`sort_by_date`);
    * обработку крайних случаев (пустые списки, некорректные форматы дат, отсутствующие ключи).
* **`test_widget.py`** — тесты модуля `widget`. Проверяют интеграцию всех компонентов для корректного отображения виджета:
    * последовательность вызовов функций;
    * обработку граничных случаев;
    * итоговый формат вывода данных для интерфейса.

### Подходы к тестированию

В проекте используются следующие техники тестирования:

* **Фикстуры (`@pytest.fixture`)** — для переиспользования тестовых данных между тестами и модулями.
* **Параметризация (`@pytest.mark.parametrize`)** — для запуска одних и тех же тестов с разными наборами входных данных, что позволяет сократить дублирование кода.
* **Проверка исключений** — тесты гарантируют, что функции корректно обрабатывают некорректные входные данные и выбрасывают ожидаемые исключения.
* **Покрытие граничных случаев** — особое внимание уделено тестированию крайних значений (пустые строки, нули, очень длинные строки и т. п.).
